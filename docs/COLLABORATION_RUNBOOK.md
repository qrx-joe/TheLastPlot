## 1. 一个项目、一个主开发、三个清晰职责

| 角色 / 工具 | 核心责任 | 绝不能做 |
|---|---|---|
| **你：产品负责人 / 验收者** | 决定范围、登录 Lux3D、选模型、体验游戏、记录截图、确认提交 | 不把 AI 声称“完成”当作真实验收 |
| **Lux3D** | 生成工厂/住宅/便利店独立 GLB；记录过程 | 不让模型自动决定经济规则与占地尺寸 |
| **Codex（唯一代码主负责人）** | 初始化工程、核心玩法、经济纯函数、Three.js 接入、测试、部署 | 不任意替换技术栈、不擅自新增后端、不覆盖 Zcode 的未合并文件 |
| **Zcode（设计审核）** | UI 布局、视觉审阅、色彩和交互文案 | 不同时修改 `src/domain` 和 `src/state`；不重写工程 |
| **仓库 docs/PRD.md v1.1** | 产品规则真值；技术规范负责实现契约；变更记入 docs/DECISIONS.md | 不允许 Agent 自行改数值、权重或通关阈值 |

**单仓库单写入者：** Codex 负责最终合并；Zcode 默认只输出设计规范/审查意见，如需直接提交 CSS，必须限定 `src/styles` 和 `src/ui`，并由 Codex 先锁定/让出文件。不要两个 Agent 同时写一个仓库，最容易损失的不是代码，是第二天上午。

## 3. Lux3D 操作 SOP

1. 打开 https://lux3d.aholo3d.cn/ ，登录并确认账户可用额度。
2. 选择文本生成 3D 或图片生成 3D；优先生产**工厂**，其次可选住宅。最低为一个真实 Lux3D GLB 用于可摆放核心建筑；其余类型可用有提示的几何体。若文生效果不稳定，可先用单物体参考图再图生 3D。
3. 工厂提示词：`A single whimsical low-poly miniature tofu factory, one tall chimney, cream walls, terracotta roof, toy-like proportion, isolated object, 360-degree geometry, no ground, no people, no readable text, cartoon style.`
4. 住宅提示词：`A single whimsical low-poly miniature house, two stories, cream walls, terracotta roof, isolated object, 360-degree geometry, no ground, no people, no readable text, cartoon style.`
5. 检查正、侧、背面；确认 GLB 或平台导出的网格模型可用。下载原件并**立即保存在 `public/models/` 的项目工作副本**；另外保存原始文件在项目外的归档目录，防止覆盖。
6. 在 `docs/ASSET_RECORD.md` 记录生成时间、版本、选择参数、截图、任务 ID（如有）、模型文件名、使用环节。生成结果与真实页面功能应以当时界面为准。
7. 本版最多做工厂、住宅、便利店三个独立资产，住宅和便利店不作为最低交付的前置条件；公园用几何体拼装。记录实际成功的类型，不为装饰反复生成。

**保底规则：** API 与网页操作可以二选一，不要求在游戏代码里调用 Lux3D。不要在客户端放密钥；如果网页生成不可用，先保存 Three.js 占位原型和错误证据，但不能把“只使用占位模型”谎称满足 Lux3D 核心素材要求。

## 4. Codex 分阶段执行话术

### 提交 0：建立环境（S0）

```text
请阅读 docs/PRD.md 和 docs/TECH_SPEC.md，严格按文件规则开发《最后一块地》。先检查当前目录和已有代码，若已有文件不要覆盖。使用 Vite + TypeScript strict + Three.js + 原生 CSS。建立 src/domain、src/scene、src/state、src/ui 的清晰模块边界；一个单独渲染循环。先完成空场景、相机、5×5 地块，执行 npm run build，报告真实结果；成功后提交 Git：chore: bootstrap web project。不要提前实现 UI 美化或新增功能。
```

### 提交 1：网格与操作（S1）

```text
只实现建筑实例数据、grid.ts 占地检查、鼠标拾取、Hover 预览、放置/移动/删除、移动取消和单步撤销，严格按 PRD 4.7 与技术规范动作表实现；工厂 2×2、住宅 1×1、公园 2×2、商店 1×1，5×5 边界和重叠检测正确。拖动超过 5 CSS 像素不能误放；HUD 不穿透；放置拾取 ground，选择拾取占地代理。移动校验排除自身，非法操作保留布局与历史。写必要单元测试和规则注释，先用原生几何体。运行测试和构建，通过后提交 Git：feat: implement grid placement。不得修改 PRD 的数字。
```

### 提交 2：经济与通关（S2）

```text
实现纯函数 evaluateCity、污染下风向判定、二选一设施、预算、平均满意度、净收益、综合评分与 win 判断。仔细阅读 PRD 4.2–4.5；写自动回归测试，测试样例满意度 90、净收益 28、花费 77、分数 73、称号「规划达标」。权重不改，公园最高 79、商店最高 83；未通关不授称号。验证污染公式与预览逐格一致、空住宅 null、数量上限、删除退款、单步撤销恢复预算和状态、非法操作保留快照；移动不重复扣费。打印测试运行结果，通过后提交 Git：feat: add economy rules and tests。不要改渲染模块内部细节。
```

### 提交 3：Lux3D 实际模型（S3）

```text
至少接入一个真实 Lux3D GLB 用于可摆放核心建筑，优先工厂；住宅/商店缺失可占位，不等待第二个模型。public/models/factory.glb 是文件位置；加载 URL 用 `${import.meta.env.BASE_URL}models/factory.glb`，不得请求 /public/models/factory.glb。实现缓存、克隆、缩放、底部贴地和失败回退；缺失/失败类型在玩家界面明确标记占位，并记录日志。GLB 仅负责显示，布局以网格为准。确认根路径和非根 base 下内容为真实 GLB，记录成功文件、来源及核心用途，不能用回退掩盖加载失败。生产构建后提交 Git：feat: integrate lux3d assets。
```

### 提交 4：UI 与游戏闭环（S4）

```text
完成玩家可见的任务说明、建筑选择卡、预算、净收益、满意度、风向箭头、放置反馈、提交结果、错误原因、移动取消、单步撤销和重置按钮。已有设施时另一卡提示先删除，不自动替换；空住宅显示「—」，未齐全不显示评分；失败可继续调整且保留布局和快照。维持 3D 世界为视觉中心，不做数据后台。核心逻辑不写在 HUD 中。跑完整通关与失败测试，通过后提交 Git：feat: finish playable game ui。
```

### 提交 5：发布（S5）

```text
完成 npm run build、npm run preview、生产模型路径检查、核心流程手动测试。写 README：玩法、运行命令、Lux3D 使用、已知局限。部署到用户授权的静态托管服务；如果缺账号或权限，提供明确的手动部署步骤和 dist 文件，不宣称部署成功。按手册第 7 节分别核对本项目交付目标、Workshop 通知和全球赛基线；准备 PDF/PPT 报告。录屏和提交由用户执行，提供可验证清单，不把部署权限等同于发送或参赛提交授权。提交 Git：chore: release and document demo。
```

每阶段都让 Codex 返回：修改了什么、运行了哪些命令、测试实际通过/失败、Git commit 哈希、还剩什么阻塞。**失败不能当作通过，未执行不能写“已验证”。**

## 5. Zcode 分工指令

```text
你是《最后一块地》的游戏 UI/UX 设计审查员，不是第二套游戏开发引擎。不要修改 domain、state、economy、placement 和构建脚本。基于既定 Three.js + 原生 HTML/CSS 工程，输出一个可直接交给 Codex 的视觉改进建议：温暖微缩城市风格、清晰的任务目标、右侧建筑卡、预算与两项经济数据、风向/污染可视化、错误反馈、结果弹窗。检查鼠标操作是否明确、选中是否高亮、颜色之外是否有文本标注；优先使用 CSS 实现，不引入 React/Vue。若被授权编辑，仅编辑 ui 和 styles 中指定文件，交付变更清单与截图，并让 Codex 集成与运行测试。
```

## 6. 最短试玩验收脚本（由你亲自执行）

1. 打开正式部署网址，不从本地开发服务器进入。
2. 开始游戏，不看说明能否明白“摆放 1 工厂 + 2 住宅 + 公园/商店二选一”？
3. 点击地图边界，让工厂越界：应拒绝放置并显示原因。
4. 放置一栋住宅到工厂下风向：满意度应下降。
5. 将住宅移到不受影响区域：满意度应恢复；预算不重复扣除。
6. 已有设施时点击另一设施卡：应提示先删除，旧设施不变。删除旧设施再放新设施，经济贡献不同且不能同时存在。
7. 按 PRD 可通关样例放置：平均满意度应为 90，净收益 28。
8. 点击「提交规划」：应成功，得分 73、称号「规划达标」；继续调整应保留建筑。
9. 分别验证放置、移动、删除后的单步撤销；撤销后无重做。非法点击与取消移动不消耗快照。重新开始应清空建筑、选择及历史，预算为 80，撤销不可用。
10. 检查至少一个真实 Lux3D 核心建筑可放置；其余占位类型须有提示。仅有截图或模型出现在展示页不算完成。
11. 空地图满意度为「—」，配置未齐全不能提交；工厂原点 (1,1) 时，预览应包含 (2,0)、(2,3)。
12. 另试完整失败布局，提交后应说明差额；继续调整不清空布局。以根路径/子路径配置的生产构建分别确认模型 URL 和内容，不将回退当成功。

## 8. 最后决策：砍功能优先级

**先删：** 实时 NPC、动态股票市场、道路寻路、多关卡、宇宙世界、复杂物理、音效系统、语言模型 NPC、账号和后端。

**必须保留：** 可玩网格摆放、二选一真实取舍、空间外部性、即时数字反馈、一个确定能过的关卡、实际 Lux3D 模型、可靠链接与视频。

**原则：** 没有实际通关的可玩闭环，漂亮模型不是游戏；没有实际 Lux3D 素材的演示，也不能谎称完成本次比赛的技术要求。
