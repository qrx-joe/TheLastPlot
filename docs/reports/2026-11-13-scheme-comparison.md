# 方案对比功能验收记录

日期：2026-11-13 · 依据：[PLAN_SCHEME_COMPARISON.md](../PLAN_SCHEME_COMPARISON.md)「同一块地，两种方案」

## 实现内容

- `src/domain/types.ts`：`GameAction` 新增 `KEEP_RESULT`。
- `src/state/gameStore.ts`：新增 `SavedScheme`（设施类型 + 只读布局 + 提交时 `Evaluation` 快照）与 `getSavedScheme()`；`KEEP_RESULT` 仅在 result 阶段、布局完整且尚无保留方案时接受，保存后回到 playing；`RESET` 同时清空撤销与保留方案。快照独立于撤销历史。
- `src/ui/HUD.ts`：结算弹窗改为方案卡片（设施名、达标状态、平均满意度、净收益、剩余预算、综合评分与称号、逐栋「住宅 (x,y) · 满意度 n · 下风向 −35 · 公园 +20」短句、未达标差额）。首份结算显示「保留X方案，试试Y」入口；保留后提交同类设施时单份展示并提示可对比；换了设施再提交时并排两份卡片，附「相比已保留的X方案，满意度 ±n.n，净收益 ±n」差值行。住宅坐标按各方案自己的布局解析（`HouseEvaluation.id` → 布局原点），不建立跨方案对应关系。
- `src/styles/main.css`：方案卡片、对比栅格（桌面并排、≤760px 上下排）、差值行与状态徽标样式；对比时弹窗放宽到 `min(700px, …)`。
- `tests/schemeComparison.test.ts`：9 项定向测试（见 AGENTS.md 测试地图）。

未改动：`economy.ts`、`validation.ts`、`gameConfig.ts` 及场景层；工作区既有的「小镇→城市」文案修改全部保留。

### 未能自动验证（环境限制，非应用缺陷）

A/B/C 完整坐标流程的 UI 走查（结算弹窗逐栋短句、「保留方案」入口点击、并排对比与差值行、Esc/继续调整、撤销后重提交、重新开始、390×844 窄屏）未能完成自动化。三重环境障碍：

1. 内嵌浏览器（IAB）：页签周期性回收，回收后 WebGL 场景停在「正在准备地块…」，跨会话复现。
2. Chrome 桌面自动化：宽屏下相机取景变化导致像素↔格子映射与标定失效；无障碍树因 60fps 画布每帧替换导致元素索引点击持续失败（坐标点击与键盘不受影响）；跨进程读取反馈文本有滞后，无法支撑迭代校正。
3. DevTools/地址栏注入：Console 粘贴未落入输入框；地址栏 `javascript:` 写入成功但被 Chrome 安全策略拦截（回填的 javascript URL 不执行）。
