# 选中建筑画布内浮动操作条验收

日期：2026-11-08。基线：S4 后 main（含 S5 发布准备进行中的未提交改动，本功能叠加其上）。本阶段仅新增交互入口，未改游戏规则、经济公式或资产。

## 背景与目标

用户反馈「点击某一个元素时应可单独取消，不能只有撤销上一步」。核实发现单栋删除功能已存在（点击建筑 → 侧栏 移动/删除/取消），但入口藏在侧栏中部小面板，可发现性差。本阶段按用户选择实现**画布内浮动操作条**：点击选中建筑后，在建筑正上方直接显示 移动/删除/取消 按钮，视线不必离开画布。

## 实现与结构影响

- 新增 `src/scene/projection.ts`：`worldToScreen` 纯函数，世界坐标 → 画布 CSS 像素；点位于相机后方时返回 null，避免浮动条悬空翻转。可单测，不依赖 WebGL。
- `ScenePresenter.getSelectionScreenAnchor()`：选中建筑顶面中心的画布像素坐标，复用既有 BUILDINGS 尺寸、MODEL_HEIGHT 与 cellToWorld，未新增几何资源。
- 新增 `src/ui/SelectionToolbar.ts`：DOM 浮动条挂在 `#scene` 内；通过注入的 `getAnchor`/`subscribeCamera`/feedback 回调工作，不直接 import Three.js；按钮派发与侧栏完全相同的 `BEGIN_MOVE`/`DELETE`/`CANCEL` 动作和文案。仅 `ready && playing && mode!=='move' && selectedBuildingId` 时显示；订阅 store、相机变化与窗口 resize 更新位置；dispose 时移除 DOM 与监听。
- `main.ts` 在场景初始化 try 块内组合并在失败/卸载路径释放；`main.css` 追加 `.selection-toolbar` 样式（白底圆角、底部小三角指向建筑、删除红色、容器 pointer-events:none 不挡画布拖拽）。
- 侧栏原有 移动/删除/取消 按钮保留，作为键盘/可发现性冗余入口；HUD、PlacementController、store、domain 均未改动。

数据流：store 状态变化 → SelectionToolbar.render() → ScenePresenter.getSelectionScreenAnchor()（读 store + 相机投影）→ CSS left/top。动作回写仍全部经 store dispatch，单步撤销快照行为与删除退款规则不变。

## 实际浏览器验证

本机 `npm run dev`（127.0.0.1:5174），内置浏览器真实点击、拖动、键盘；DOM 读取仅取文本与位置，未注入状态。

| 场景 | 实际结果 |
|---|---|
| 点击选中工厂 | 浮动条出现于建筑正上方，含 移动/删除（红）/取消，底部三角指向建筑，蓝色选中描边正常 |
| 浮动条「删除」 | 建筑删除、预算 80 全额退回、浮动条隐藏、撤销一步可用 |
| 浮动条「移动」 | 进入移动模式（移动中：工厂），浮动条按设计隐藏；点新格子后「已移动到 (0,1)」并取消选中 |
| 重新选中已移动建筑 | 浮动条在新位置（左上）重现，坐标随建筑位置变化 |
| 拖动旋转相机 | 浮动条位置实时跟随（多次采样 left/top 持续变化），选中与显示保持；复核截图三角仍指向建筑，右侧面板与底部无遮挡 |
| Esc 取消 | 「已取消当前操作」，浮动条隐藏 |

测试环境备注（非页面缺陷）：内置浏览器首帧渲染就绪约需十余秒，等待后正常；其 Playwright 角色定位点击在 `<dialog>` 内按钮上超时，改用 DOM 节点点击完成同样交互；一次大幅拖动命令超时但旋转实际生效。

## 范围与剩余限制

- 浮动条不检测遮挡：建筑被其他建筑挡住时仍显示在投影位置（描边高亮本就不受遮挡影响，视觉可接受）。
- 相机后方/画布外锚点按 null 隐藏，未做边缘钳制（当前网格与相机约束下建筑不会投影到画布外）。
- 仅在 1280×720 内置浏览器验证；窄屏（390×844）下浮动条与建筑卡片的相对位置未单独复测。真实触屏、无障碍焦点顺序未测。
- 侧栏按钮与浮动条双入口并存，状态渲染逻辑各自独立实现（均从同一 store 派生），文案一致但未抽象共享。
