# S1 网格与建筑编辑验收

日期：2026年11月8日。结果：S1 完成，可继续 S2。当前为几何占位建筑编辑版，不代表经济系统、通关游戏或 Lux3D 接入已经完成。

## 实现与结构影响

输入/HUD → gameStore.dispatch → domain 校验 → 不可变 GameState → ScenePresenter/HUD。预览与真实放置复用 canPlace，视觉尺寸不决定占地。

- data/gameConfig.ts：加入 PRD 原值的建筑尺寸、费用、数量上限、初始预算与 5 像素拖动阈值；界面从该配置取值。
- domain/types.ts、grid.ts、validation.ts：建筑实例、占地、整数/边界/冲突、配额、设施互斥与建造预算。收益、污染、满意度、评分暂不添加。
- state/gameStore.ts：动作、ID 唯一性、移动排除自身、删除全额退款、冻结状态与私有单步快照；无效动作不改变状态或历史。原位移动不新增快照，重置不支持撤销。
- scene/coordinates.ts：增加世界到网格反向转换；SceneManager 增加连续拾取面与相机变更订阅，保留唯一渲染循环。
- ScenePresenter：四类几何占位建筑、按占地生成的选择代理、选中框与绿/红占地预览；几何体和材质复用，销毁时统一释放。
- PlacementController、pointerGesture：只在完整短按结束后派发动作，追踪整段最大位移；拖出再回原点仍算拖动；HUD 不在 canvas 事件路径中。Esc、取消和离开画布有对应处理。
- HUD、index.html、CSS：仅加入编辑必需的卡片、数量、预算、选中操作、撤销/重置和反馈。直接进入 playing 编辑，启动页与提交/结果动作按后续阶段实现。

## 浏览器验收

Windows Codex 内置浏览器，1920×1080，使用生产构建 preview。以下均通过实际按钮、原生点击、拖动、滚轮与 Esc 操作，未通过脚本直接修改游戏状态。

| 场景 | 实际观察 |
|---|---|
| 工厂越界 | 东北角放 2×2 工厂被拒绝，红色完整占地预览与原因可见，预算仍为 80 |
| 拖动与滚轮 | 住宅待放置时旋转/缩放相机，住宅仍为 0/2，预算保持 45；复位后正常放置 |
| 完整公园配置 | 工厂 (0,0)，住宅 (0,4)/(4,4)，公园 (1,2)，剩余 3；商店卡因设施互斥禁用 |
| 放置撤销 | 第二栋住宅撤销后恢复 1/2、预算 33，且无第二次撤销；重新放置正常 |
| 自身占地移动 | 工厂从 (0,0) 移到 (1,0)，与旧占地部分重叠仍合法，预算保持 3 |
| 非法移动及取消 | 移到 (4,4) 同时越界和重叠，被拒绝；Esc 后撤销仍将工厂恢复到 (0,0)，预算不变 |
| 删除与恢复 | 删除工厂后预算从 3 到 38，撤销后恢复原建筑、预算回到 3 |
| 设施更换 | 删除公园后预算 21，商店可选；在 (2,2) 放商店后剩余 6，公园卡禁用 |
| 缩放后拾取 | 缩小视角后点击右侧住宅，选中信息仍为住宅 (4,4) |
| 重新开始 | 全部建筑/选择清空，预算 80，撤销不可用；随后可重新完成公园配置 |
| 最终状态与日志 | canvas 数量 1；最终预算 3，1 工厂/2 住宅/1 公园；捕获的 warn/error 为空 |

本地截图与可见 HUD 记录位于 output/s1-acceptance，不进入 Git。验收后预览服务停止；再次查看运行 npm run dev。截图中的占位建筑不宣称为 Lux3D 产物。
