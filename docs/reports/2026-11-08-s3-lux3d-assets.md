# S3 Lux3D 真实资产接入验收

日期：2026年11月8日。结果：S3 完成，可进入 S4。真实 Lux3D 贴图工厂已作为可操作的核心建筑接入；住宅、公园和商店继续使用逐类标明的几何占位模型。当前仍为本地构建，没有部署。

## 资产与结构影响

工厂通过 Lux3D 中国站网页完成参考图、网格和一次材质重绘。用户完成登录验证；助手执行生成设置、三次生成类提交、正/侧/背面检查、GLB 下载、结构检查与游戏集成。最终资产 ID 57868，来源、提示词、参数、原件和哈希见 [ASSET_RECORD](../ASSET_RECORD.md)。未将网页流程描述为已经接通 OpenAPI 或 MCP。

最终 GLB 为 7,290,192 bytes、83,958 个三角面、1 个网格、1 个材质，内嵌两张 2048×2048 PNG；不存在必需压缩扩展或外部资源。官方 artifact_delivery inspect 校验为有效 glTF 2.0，工作副本与原始贴图 GLB 的 SHA-256 一致：`71fc2d854cdcd45034921066ab6e477ba247c9b9a695063f39b247e7e39e1df4`。

数据流：已有布局 → ScenePresenter → AssetLoader 共享缓存的独立实例；资源加载状态另行通知 HUD。输入、预算、污染、满意度和评分仍经 store/domain，模型包围盒只用于显示归一化。

- src/data/assetConfig.ts：只登记真实已提供的 factory.glb，并统一显示高度上限；缺失的可选类型不发起网络请求。
- src/scene/AssetLoader.ts：使用 BASE_URL 生成 URL；按建筑类型合并并发加载并缓存模板，克隆共享几何体/材质但独立变换。保留比例、水平居中、底面归零，限制在显示尺寸内。失败状态不伪装为成功、不自动无限重试；卸载后晚到的结果只释放资源，不回写页面。
- src/scene/ScenePresenter.ts：优先使用真实模型，加载中/失败/缺失时沿用几何体；资源状态变化时按当前布局重画。删除建筑不释放共享缓存，拾取仍使用逻辑占地代理。
- src/main.ts、src/ui/HUD.ts：组合并释放资产服务，逐类型显示「加载中」「Lux3D 已加载」「加载失败，使用占位模型」或「使用占位模型」。
- public/models/factory.glb：原始贴图工厂工作副本。未新增生产依赖，也未修改游戏配置、domain、store、相机或坐标规则。
